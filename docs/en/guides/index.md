# Guides

Task-oriented how-tos: one page per shipped recipe, naming the command it takes, what its answer rests on, and what its closing line means. For the recipes side by side, see the [reference](../references/index.md).

## Before a real run

- [Connectivity check](connectivity-check.md) — prove both MCP servers are reachable, authenticated, and answering, and read what a failure is telling you

## Ask about one garden

- [Plant master data check](plant-master-data-check.md) — which plants lack the master data a later analysis would need, and what each gap prevents
- [Nutrient imbalance check](nutrient-imbalance-check.md) — under- or oversupplied, or unable to take up what is there, for one plant
- [Pest pressure check](pest-pressure-check.md) — whether a pest or disease suspicion survives the record
- [Species baseline check](species-baseline-check.md) — whether the species record a plant depends on is plausible, and what its lifecycle is
- [Diary analysis queue](diary-analysis-queue.md) — analyse one waiting diary entry, work through the queue, or run it on a schedule

## Work on this repository

- [Domain review](domain-review.md) — read a recipe or spec as one grower persona and report what that grower would do with it
- [Provider surface check](provider-surface-check.md) — inventory the tools a run actually holds under the current provider
- [Provider plugin check](provider-plugin-check.md) — whether plugin skills, plugin agents, and project agents are reachable from a run
